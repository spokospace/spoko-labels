# Backward compatibility

What this project treats as a protected contract surface, and how a change to one must be handled. Review skills check PRs against this file; implementation skills warn when a change would break it.

## Versioning

All packages follow [semver](https://semver.org). Until `1.0.0`, a minor version may break a contract, but only with a changelog entry under **Breaking** and a migration note in the package README. From `1.0.0`, breaking changes need a major version and a deprecation window of at least one minor release where the old form still works and warns.

## Protected surfaces

| Surface | Where | Breaking change | Required path |
|---|---|---|---|
| Package public API | exports of each `@spokospace/labels-*` package entry point; today `@spokospace/labels-core` (`packages/core/src/index.ts`): `Printer` (static `connect`, `info`, `readRfid`, `print`, `disconnect`, `connected`) with `PrintOptions` (`density`, `copies`, `offsetMm`, `onProgress`, `signal`), `PrinterInfo`, `PrintProgress`, `RfidInfo`; `WebBluetoothTransport`; the `Transport` interface; `imageToRows` and `ImageLike`; `B1` and `PrinterModel` (including `offsetMm` and `dotsPerMm`); the codec (`encodePacket`, `PacketParser`, `Packet`, `ParsedFrame`, `parseRfid`, `encodeRows`, `shiftRows`, `MAX_ROWS`, `CMD`, `INFO_KEY`); the error classes. `@spokospace/labels-render` (`packages/render/src/index.ts`): `validateTemplate`, `render`, `loadFonts`, `bundledFonts`, `browserEnvironment`, `TemplateError`, `TEMPLATE_VERSION`, `DEFAULTS`, `LIMITS`, and the exported types (`Template` and its element types, `Normalized*`, `TemplateIssue`, `IssueCode`, `RenderOptions`, `RenderResult`, `RenderWarning`, `RenderData`, `FontSource`, `FontRegistry`, `RenderEnvironment`, `CanvasLike`, `Context2DLike`); `@spokospace/labels-niimbot` (see Niimbot import output below) | removing or renaming an export, changing a signature or a return shape, tightening accepted input, changing a default that moves the printed image (such as `offsetMm`) | deprecate first (JSDoc `@deprecated` + console warning), changelog, version bump |
| Error codes | the `code` string of every `LabelsCoreError` (`ErrorCode`: `bluetooth-unsupported`, `chooser-cancelled`, `device-unreachable`, `disconnected`, `no-response`, `refused`, `print-timeout`, `busy`, `aborted`, `invalid-argument`, `protocol`) and the extra fields (`step`) | removing or renaming a code, or reporting a situation under a different code | callers translate codes into user text, so treat a code like an export: deprecation window, changelog |
| Template format | the template JSON schema, version 1 (`packages/render/src/schema/types.ts`, described in `packages/render/README.md`): field names, units (mm), defaults (`fit: "shrink"`, `minSize: 0.75`, `level: "L"`, `safeMargin: 0`, …), the bundled family names `"Viga"` and `"HarmonyOS Sans"`, and the render issue codes | removing a field, changing units or meaning of a field, rendering an existing template differently on purpose | bump the schema version and ship a migration from the previous version; old templates keep rendering |
| Niimbot import output | `packages/niimbot` (`packages/niimbot/src/index.ts`): `extractTemplates` with its result shape (`ExtractResult`, `ExtractWarning`, `ExtractWarningCode`) and warning codes (`no-templates-found`, `duplicate-template`, `scan-incomplete`); `importTemplates` with `ImportOptions` (`fonts`, `fontCatalog`, `defaultSize`), its result shape (`ImportResult`, `ImportedTemplate`, `ImportFailure`, `ImportSource`, `ImportWarning`), the warning and failure codes (`unsupported-element`, `rotated-element`, `unsupported-style` with its `feature` names, `unknown-font`, `unrecognized-binding`, `value-clamped`, `invalid-element`, `invalid-input`, `unknown-size`, `invalid-template`), `NIIMBOT_FONT_FAMILIES` (the code → family table and its family names), `LETTER_SPACING_SCALE` (1.65), `NiimbotTemplate` (including `rotate`), `ImportedTemplate.printRotation` and `PrintRotation`; `niimbotFonts` (a `readonly FontSource[]`) and the family names it registers (`"Inconsolata"` regular and bold, `"Baloo Paaji"`, `"Markazi Text"`, `"Cookie"`), which must keep matching `NIIMBOT_FONT_FAMILIES`; and the emitted template JSON itself, pinned by `test/__snapshots__/import.test.ts.snap` | different JSON for the same Niimbot input and options (a changed mapping, rounding, clamping, font table entry or default), removing or renaming an export, option or code, removing a family or face from `niimbotFonts` or registering it under a different name, replacing a font file or changing its metrics or ranges (stored templates print differently) | changelog entry and a deliberately updated snapshot; a change that alters templates users already imported and stored also needs a minor version bump before 1.0 and a migration note |
| Embed API | the dialog's options, events and URL/hash parameters (*planned*) | removing or renaming an option, event or parameter; changing its meaning | deprecation window, changelog |
| Web app deep links | `apps/web` URL/hash parameters such as `#add=…` (*planned*) | removing or renaming a parameter; links that worked stop working | keep accepting the old form for at least one minor release |
| Printer protocol behavior | `packages/core` (the print sequence in `printer.ts`, the codec in `protocol/`) | a printer model that printed correctly stops printing correctly | hardware evidence for every supported model in the PR; never a silent change |

## Not a contract

- Internal modules not exported from a package entry point.
- Error `message` text (only the `code` is a contract).
- The exact pixels of a label between minor versions, as long as layout, text and QR content stay the same (anti-aliasing and threshold tweaks are allowed; golden images are updated in the same PR).
- Files under `.ai/` and `.claude/`.
